# 电鸭公开招聘 RSS 数据源调研（2026-07-30）

采样时间：2026-07-30 15:55--15:57 Asia/Shanghai（匿名、未登录；未保存 Cookie/Token）。本报告只使用电鸭公开页面和该站直接返回的 RSS/HTTP 响应；示例仅保留最少标题/字段证据，不转载帖文正文。

## 结论摘要

**已证实**：电鸭官网页脚的 RSS 链接是 `https://eleduck.com/feed/latest.xml`；该 URL 匿名返回 RSS 2.0 XML（HTTP 200，`application/xml; charset=utf-8`）。它是“最新帖子”混合流，不是招聘专属 feed：25 条样本同时有招聘、问答、产品自荐、招募合伙人等。RSS 不提供分类、标签、作者、正文原文链接字段，也没有 ETag/Last-Modified 或缓存控制字段；因此应以 `guid` 去重、低频全量轮询，不能做可靠的服务器条件拉取。

**实施边界建议**：仅实现一个匿名的 RSS 拉取器和本地状态库：保存 `guid`、`link`、`title`、`pubDate`、`description` 摘要、首次/最后一次看见时间和分类置信度。不得把它宣称为“官方招聘流”，不得抓取验证页或登录后页面，不得把 RSS 缺失当作删除事件，也不得保存/再分发联系方式等可能出现在用户帖内的个人信息。

**已证实**的 item 字段仅为：`title`、`description`、`link`、`guid`、`pubDate`。未见 `category`、标签、作者、`enclosure`、`comments`、独立“原文链接”或更新时间字段。`link` 即站内帖详情 URL（形如 `https://eleduck.com/posts/dDfXdD`）；没有外部原文 URL 结构可用。

## 标识、稳定性与正文

### GUID

**已证实（当前样本）**：25/25 项的 `guid` 是与 `link` 完全相同的 HTTPS 帖 URL，形如 `https://eleduck.com/posts/<6-char-id>`，并显式为 `isPermaLink="true"`。同一份窗口在约 3 秒内取得两次，25 个共同项目的 `guid` 均相同（25/25）；当前第二次样本中也是 25/25 的 `guid == link`。

**样本推断**：`guid` 是目前最合适的本地幂等键；同时保存 URL，可在未来格式变化时复核。

**未知/需后续验证**：这不能证明 GUID 跨数周、编辑、迁移或下线后仍永久稳定；也无法证明旧 URL 一定可访问。

### 正文完整性

**样本推断**：description 很可能是截断摘要而非完整正文。25 条中有 14 条的 XML 文本长度恰为 200 字符，另有短于 200 的项；例如首项摘要在一个未完句后结束。该形态强烈指向长度上限。

**未知/需后续验证**：匿名访问首项详情 `https://eleduck.com/posts/dDfXdD` 在本次采样返回 302 到 `/verification?...`，无法以详情页逐字比较，故不能把“全部都截断”作为已证实结论。实施时应将 `description` 视为不完整、未净化的用户提供摘要。

## 招聘识别：可解释的候选规则（不是官方分类）

RSS 没有分类/标签，且整个最新流混合主题；以下只能是**样本推断**的文本规则，输出应保留 `uncertain` 和命中理由，而不覆盖原始字段。

| 候选类别 | 建议正向特征 | 当前匿名样本中的最少证据 | 重要反例/边界 |
| --- | --- | --- | --- |
| 招聘 | `招聘`、`招聘岗位`、`直招`、`岗位`、`全职/兼职`，并同时出现职责、任职要求、薪酬或投递/联系语义 | “【香港直招】全远程新媒体助理 在家工作”、 “【招聘岗位】网站运营及SEO专员（澳洲建材电商｜全职远程）” | “【寻技术开发团队】…”含寻人/需求，但更像项目外包；不要仅因“寻找”归招聘。 |
| 求职 | `求职`、`找工作`、`寻求岗位`、`可入职`、简历/作品集，且主体是候选人提供能力 | 当前 25 条没有足够清晰的正例 | “安卓开发兼职开发调试”是需求方列要求，不是求职；词形含“开发”不能决定主体。 |
| 外包 | `外包`、`项目需求`、`开发团队`、`交付`、预算/报价/招标，且购买的是项目成果 | “【寻技术开发团队】社群智能运营管理系统开发需求”；“高级 PHP… ”正文摘要也自称服务德国客户的“技术外包岗位” | 后者虽含“外包”仍在招个人岗位；应允许 `招聘 + 外包背景` 双标签或优先标 uncertain。 |
| 合伙 | `合伙人`、`共同创业`、股权、投资人/融资且寻求共同承担事业 | “ai nas系统…招募合伙人（测试、推广、投资）” | 单纯“合作”或客户合作不等于合伙。 |
| 广告/自荐 | 产品/服务推广、优惠/导流、`自荐帖`，而无明确岗位/项目采购 | “做了个 AI API 网关…”明确自称自荐帖 | 自荐帖可能同时包含招聘或合作请求；不得自动丢弃。 |
| 讨论 | 问题、经验交流、观点讨论，且没有明确供给/招募交易动作 | “为什么很多工具类小程序都火不了？独立开发者求交流”；“咸鱼上的百度收录服务靠谱吗” | 帖子也可在讨论正文中推广产品；仅标题判断会误分。 |
| uncertain | 无明确主体/交易动作、多个类别同分，或摘要已截断 | “微软账号自动化注册 GUI 工具”及任何只含产品/技术词的条目 | 不以敏感、违规或可疑业务词自动做内容判断；它们是安全审查问题，不是招聘分类证据。 |

建议采取规则优先级而非单关键词：先判“谁在寻求什么”（雇主岗位 / 候选人 / 项目交付 / 合伙），再用职责、投递、预算、薪酬等佐证；冲突或摘要近 200 字符时降置信度。保留多标签和 `uncertain`，以人工抽检校准。

## 删除、更新与增量

**已证实**：feed 没有 `deleted`、tombstone、`lastUpdated` 或项目级更新时间字段；仅有发布 `pubDate`。channel 的 `lastBuildDate` 会随两次采样推进（例如 07:56:58 GMT 到 07:57:01 GMT），这不是项目修改证明。

**未知/需后续验证**：项目从 feed 消失可能是新增挤出 25 条窗口、排序/审核变化、删除或下线，RSS 无法区分；不能据此执行删除。详情页在匿名访问中受验证限制，不能用高频详情探测弥补。

低频增量建议：每 15--30 分钟带随机抖动 GET 一次，设置合理超时、退避和单 host 限速；以 `guid` 去重，保留最近窗口的“最后看见”而不删除历史记录。请求失败时重试应指数退避；未收到 ETag/Last-Modified 时不要假设可作条件 GET。若未来响应开始提供验证器，再实测 304 后才启用条件请求。由于只有 25 条窗口，首次上线和较长故障恢复应报告可能漏项，而不是回补猜测。

## 合规、稳定性与安全边界

- **合规/隐私**：只处理公开 RSS 最小字段；用户帖可能含联系方式、薪酬、简历或其他个人资料，采集端应数据最小化、访问控制、设定短保留期，并避免二次公开原文。电鸭规则/robots 对自动化的具体许可本次未验证，生产接入前需复核站方公开政策或获得许可。
- **稳定性**：这是未版本化、无缓存验证器、无分页/分类字段的单一最新流；字段、窗口大小、验证页策略均可能变化。必须有 XML 解析失败监控、schema 变更告警、空 feed 告警和 URL allowlist。
- **安全**：将 XML/CDATA、标题、description 和站外链接均视为不可信输入；禁止渲染原始 HTML、禁止跟随帖内链接进行抓取、限制响应大小与重定向、使用防 XXE 的解析配置。仅允许 `https://eleduck.com/feed/latest.xml` 及已验证的同站 `link` 作为引用，不通过自动化绕过 `/verification`。
