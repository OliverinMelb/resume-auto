# Domain documentation

- layout: `single`

Use root `CONTEXT.md` as the domain glossary and `docs/adr/` for durable decisions.

If a referenced domain document does not exist, continue without inventing its contents. Read the relevant glossary and ADRs before naming interfaces, tests, specs, or tickets. Use one term per concept and challenge overloaded vocabulary before it reaches an interface. Existing ADRs outrank a new proposal until an explicit superseding decision is recorded. Update domain docs only when their paths are explicitly owned by the task.
