# 扩展电鸭公开职位采集

## 目标

把电鸭运行时的主发现源从仅含最新 25 条的 RSS，改为电鸭生产前端使用的匿名公开职位 JSON 列表。默认读取最近 20 页，最多检查 500 条列表记录，并沿用现有分类、评分、人工确认、项目入库和去重流程。

## 已确认现状

- RSS 固定只给最新 25 条混合帖子。
- 第一方接口 `GET https://svc.eleduck.com/api/v1/jobs_channel/posts?page=N&sort=-published_at` 匿名可用，每页 25 条，并返回 `posts` 与 `pager`。
- 2026-08-03 实测第 20 页最旧记录约为 2026-05-10，最近 20 页覆盖约三个月；数量和时间窗口是动态值，不能写死在测试中。
- 网页招聘入口会跳转验证码，但该 JSON 接口是电鸭生产前端自身使用的公开读取接口。

调研证据保存在 `workflow/tasks/20260803-192158-171762-task/research.md`。

## 行为

1. 使用独立的电鸭公开职位列表读取器与严格 JSON 解析器。
2. 预览在用户点击后读取最近 20 页；研究在首次运行时最多读取 20 页，之后遇到一整页均为已见 ID 时提前停止。
3. 只保留公开、未删除、未隐藏、未关闭且状态为 `published` 的列表项。
4. 只抽取 `id`、标题、摘要、发布时间和识别所需的最小公开字段；帖子 URL 由官方 `/posts/{id}` 路由构造。
5. 文本继续经过现有脱敏与长度限制，再交给现有分类器、评分器和入库层。
6. 请求失败、重定向、非 JSON、超限响应、页码不一致或 schema 错误均安全失败；正式研究不得推进游标或写入项目。
7. UI 明确显示“公开职位列表（最近 20 页）”和最多 500 条，不再让用户误以为只有 RSS 的 25 条。

## 非目标

- 不遍历全部约 446 页历史数据。
- 不打开帖子详情页，不获取联系方式。
- 不使用登录 cookie、验证码结果或用户浏览器会话。
- 不绕过网站验证页面。
- 不增加复杂筛选条件，也不改变现有简历项目/岗位评分语义。

## 安全与资源边界

- 只允许固定 HTTPS 主机 `svc.eleduck.com` 和固定路径 `/api/v1/jobs_channel/posts`。
- 禁止重定向；单页响应大小、总页数、标题和摘要长度均设硬上限。
- 页码为正整数且硬上限 20 页；请求顺序执行并设置超时。
- 不保存发布者资料、头像、评论或响应中的其他非必要字段。

## 验收标准

- 跨页解析、按 ID 去重、过滤关闭项、整页已见提前停止均有固定测试。
- 恶意 URL、重定向、错误内容类型、超限响应、错误 pager 和坏 schema 均安全失败。
- 预览零写入；采集失败时研究零写入且游标不推进。
- 页面保持手动触发，明确最近 20 页和最多 500 条。
- 电鸭专项测试、全库测试、编译检查、`git diff --check` 和真实只读页面验证通过。
